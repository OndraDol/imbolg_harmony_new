# A1: Inicializace a převzetí zadání

## Účel a hranice

Připravit trvalé zadání, ze kterého další model provede jednotlivé fáze bez znalosti této konverzace. A1 nesestavuje web, nestahuje média, neinstaluje webové závislosti a nemění externí účty. Poslední upřesnění uživatele má přednost před obecným „implementuj plán“.

## Vstupy

Schválený plán z konverzace, předchozí read-only průzkum, prázdný projekt, dodaný přístup Webnode. Před opakováním A1 přečíst skutečný Git stav; nepřepisovat hotovou dokumentaci ani již uložený přístup bez porovnání.

## Postup

1. Ověřit absolutní cestu a případný nadřazený Git. Pokud projekt není repozitář, založit lokální Git s větví main. Nezakládat remote a nic nepushovat.
2. Uložit README, AGENTS a dokumenty odkazované v README. Vytvořit zvláštní zadání pro A1–A6, B1–B2 a C1–C2.
3. Do každého zadání uvést účel, vstupy, kroky, výstupy, ověření, podmínku DONE, známé překážky a bod zastavení.
4. Oddělit pozorování od předpokladů. Zapsat neověřenou administraci, soupis médií, identitu schránky a parametry skutečného účtu.
5. Založit .gitignore dřív než přístupový soubor. Uložit přístup pomocí Windows DPAPI PSCredential, nikoli plaintext .env nebo Markdown.
6. Načíst soubor zpět bez výpisu hesla a porovnat hodnoty jen jako boolean. Ověřit, že XML neobsahuje otevřené heslo a soubor je ignorovaný Gitem.
7. Zkontrolovat odkazy v dokumentaci, existenci všech fází, návaznosti, shodu menu a cen. Nenahrazovat neznámé údaje zástupnými „ověřeno“.
8. Zapsat ověření do WORKLOG, aktualizovat STATUS a skončit. Další fázi nespouštět.

## Výstup a kontrola

Existují všechny dokumenty z README, deset souborů fází a ignorovaný šifrovaný přístup. Budoucí npm příkazy jsou jasně označené jako neexistující. Ve složce nejsou src, dist, package.json ani závislosti webu.

Kontroly Git spouštět s explicitním `git -C <absolutní projekt>`. Použít `status --short`, `check-ignore -v .secrets/webnode.credential.xml` a `diff --check` pro sledované změny. Před případným lokálním commitem zkontrolovat jeho přesný seznam souborů. Remote ani push nejsou součástí A1.

DONE pouze pokud dokumentace umožňuje samostatné zadávání fází a bezpečnost přístupů byla ověřená. Selhání DPAPI znamená konkrétní překážku; nesmí vést k tichému plaintext uložení. Při dalším spuštění už hotové A1 neopakovat šifrování nebo init bez důvodu.
