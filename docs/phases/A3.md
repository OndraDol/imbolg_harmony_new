# A3: Technický základ a základní vzhled

## Účel a vstupy

Připravit jednoduchou funkční konstrukci pro všech deset stránek a pozdější redesign. Vstup: A1, kompletní veřejný základ A2, ARCHITECTURE a skutečné zdrojové layouty. Nepřepisovat texty, neřešit finální umělecký redesign a neimplementovat SMTP.

## Postup

1. Ověřit skutečný stav A2 a prostředí. Pokud chybí obsahový základ, nevyplňovat stránky vymyšleným textem a nezačít náhradní rešerši místo A2.
2. Založit package.json jako private projekt a Eleventy/Nunjucks. Použít dostupný Node 24.14.1 nebo kompatibilní ověřený Node, verzi uvést. Před instalací projít Node dependency runbook, ověřit přesné verze, původ a bezpečnost; lockfile uložit. Instalaci začít s vypnutými lifecycle skripty. Nezavádět další frontend framework.
3. Vytvořit strukturu src podle ARCHITECTURE a pevný seznam deseti permalinků. Žádné odvození URL z nového nadpisu, které by změnilo původní adresu.
4. Založit sdílený layout, hlavičku, patičku a navigaci. Data menu na jednom místě v původním pořadí. Aktivní odkaz označit aria-current. Přidat přeskočení na hlavní obsah a viditelný focus.
5. Vytvořit komponenty textového bloku, obrazu a galerie s chráněnými datovými ID. Na všech stránkách mohou být v této fázi jen skutečné existující nadpisy a nezbytná kostra; nesmějí vzniknout nové marketingové texty. Stav neoznačovat jako obsahově hotový.
6. Základní styl podle ARCHITECTURE: přehledná malá hlavička, čitelná sazba, žádné zbytečné efekty. Všechny volby vzhledu centralizovat v CSS proměnných, aby B1 nemusela zasahovat do obsahu.
7. Mobilní menu zpřístupnit i bez JS. Deset položek se nesmí ztratit, překrýt nebo vyžadovat přesné míření. Fotografie nemají přesáhnout šířku viewportu, text držet na rozumné čtecí šířce.
8. Založit npm run dev, build a verify. Verify nyní kontroluje jen skutečně implementované vlastnosti A3; v reportu výslovně uvést, že úplnost obsahu a PHP testy přijdou později. Chybějící kontrolu neprezentovat jako PASS.
9. Nastavit lang=cs, UTF-8, viewport a původní titulky. Výstup jen do dist z explicitně vybraných veřejných vstupů. Nekopírovat docs, archive, .secrets ani private.
10. Aktualizovat README skutečnými příkazy a přístupy k lokálnímu náhledu. Zapsat nainstalované verze, důvody závislostí a výsledky do WORKLOG.

## Ověření

Spustit npm run build a verify a prohlédnout výstup. Přes lokální HTTP otevřít všech deset URL, ověřit navigaci a kódování. V browseru ověřit 360 a 1440 px, ovládání klávesnicí a vypnutý JavaScript. Testovat skutečný menu stav, ne pouze přítomnost odkazů v HTML.

Zkontrolovat, že dist neobsahuje dokumentaci, privátní adresáře, přístupy, originální archiv nebo node_modules. Ověřit obsah lockfile a výsledek kontroly závislostí; neprovádět nekontrolované npm audit fix --force.

## DONE a zastavení

Deset cest funguje, menu zachovává pořadí a je přístupné bez JS, layout nepřetéká a příkazy jsou reprodukovatelné. Neexistuje žádné tvrzení o hotovém přenosu obsahu nebo formuláři. Zapsat důkazy do STATUS a skončit před A4.
