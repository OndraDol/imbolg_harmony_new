# A5: Kontaktní formulář

## Účel a hranice

Implementovat lokálně ověřený formulář, který bude později doručovat na Seznam. A4 musí být hotová; strukturu a required pole převzít z evidence A2. **Žádné skutečné e-maily při vývoji neodesílat.** Přístup do Seznamu není potřeba. SMTP konfiguraci produkce zatím nevymýšlet.

## Postup

1. Načíst ARCHITECTURE a archivovaný formulář. Zachovat jeho pole a umístění na úvodu. Pro chybový návrat použít stejný formulářový partial; nekopírovat druhou neudržovanou sadu polí.
2. Najít dostupné lokální PHP/Composer. Pokud nejsou, připravit lokální izolované prostředí z oficiálních distribucí, ověřit podpis/checksum a verzi, nepřidávat globálně náhodný balíček. PHP 8.3 odpovídá cílovému hostingu. Zapsat skutečné cesty a příkazy.
3. PHPMailer získat z oficiálního balíku, uzamknout verzi a Composer lockfile, zkontrolovat závislosti a zbytečné plugins/scripts. Vendor připravit lokálně, na hostingu nevyžadovat Composer. Přístupové údaje nepatří do composer.json.
4. Vytvořit POST /api/contact.php a neveřejnou aplikační část podle ARCHITECTURE. Statická část nesmí načítat PHP zdroj jako text. PHP náhled i testovací fixture použijí kanonický strom public/private a stejnou relativní cestu endpoint → private/app/bootstrap.php jako release. DocumentRoot je výhradně public; nespouštět server nad kořenem projektu nebo nad rodičem obou složek.
5. Validovat typ, velikost a obsah všech vstupů na serveru. Odmítnout array místo textu, neplatný e-mail, nečekané řídicí znaky v hlavičkových polích, nadměrná data a jinou HTTP metodu. Zachovat české Unicode znaky ve jménu a zprávě. Escapovat návrat vstupů do HTML.
6. Recipient napevno Seznam. From je pouze konfigurovaná ověřená doménová schránka, Reply-To pouze validovaný e-mail návštěvníka. Žádný parametr požadavku nesmí určovat SMTP server, příjemce, transport nebo cestu k souboru.
7. Přidat honeypot a konfigurovatelný rate limit mimo veřejný adresář. Souběžné požadavky nesmějí limit obejít závodem; stav časově čistit. Neukládat do rate-limit logu celé zprávy nebo e-maily. Nenastavit anonymní formulář jako veřejný relay.
8. Při chybě vypsat české vysvětlení a bezpečně zachovat validní uživatelské vstupy. Totéž funguje bez JS. Po úspěchu uvést pravdivý stav předání zprávy; výpadek SMTP nikdy nepřevést na úspěch.
9. Výchozí produkční transport bez validní konfigurace selže bezpečně. Lokální capture režim zapisuje jen syntetické testy do private mimo DocumentRoot a odpověď jej označuje jako test. Před produkčním balením capture vyloučit nebo znemožnit jeho aktivaci zvenku.
10. Připravit stručnou informaci o zpracování údajů podle skutečného toku dat. Nevymýšlet IČO, dobu uchování, souhlas nebo podmínky majitelky. Neověřené údaje evidovat jako položky k doplnění před publikací v C1. Volitelnou analytiku ani CAPTCHA třetí strany automaticky nepřidávat.
11. Založit npm run test:form, který lokálně spustí relevantní testy a prokazatelně nepoužije produkční SMTP. README doplnit PHP náhled, konfiguraci, ukončení serveru a omezení statického dev náhledu.

## Povinné testovací scénáře

| Scénář | Očekávaný důkaz |
|---|---|
| Validní syntetická zpráva s diakritikou | Jedna lokálně zachycená zpráva, správný recipient/From/Reply-To |
| Chybějící povinné pole / neplatný e-mail | Chyba u pole, nic nepředáno transportu |
| Zpráva prázdná | Chování odpovídá skutečnému required původního formuláře |
| Pole jako array / velký payload / CRLF v e-mailu | Bezpečné odmítnutí, žádná injekce hlaviček nebo PHP chyba |
| HTML/script ve zprávě či jménu | Při návratu do HTML se nespustí |
| Honeypot vyplněný / překročený limit | Neodesílá, limit nelze obejít falešným proxy headerem |
| Metoda GET místo POST | Endpoint neodesílá ani nevystavuje konfiguraci |
| Chybějící konfigurace / výpadek transportu | Pravdivá chyba, žádný falešný úspěch |
| JavaScript vypnutý | Odeslání do capture a oprava chyby jsou použitelné |
| HTTP pokus načíst private/config/vendor | Nejsou veřejně dostupné |

## DONE a zastavení

Lokální testy i browser cesta fungují, žádný e-mail neopustil testovací prostředí a chybové stavy jsou ověřené. V reportu musí být „produkční SMTP a skutečné doručení neověřené“. Příprava návrhu textu o soukromí není potvrzení jeho schválení. Aktualizovat README, STATUS a WORKLOG, skončit před A6.
