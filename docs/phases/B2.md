# B2: Regresní kontrola a schválení vzhledu

## Vstupy a cíl

Redesign B1, předchozí ověřená verze A6, nezměněný zdrojový základ A2 a výsledky testů. Cílem je prokázat, že nový vzhled nic neztratil nebo nerozbil, a získat schválení majitelky. Kontrola není oprávnění znovu kompletně přestavět design.

## Postup

1. Porovnat změněné soubory A6 → B1. Zvlášť zkontrolovat, zda se neměnily baseline, obsahová data, permalink, recipient, SMTP nebo validace. Neočekávanou změnu vyšetřit, nepřijmout ji jen kvůli zelenému testu.
2. Spustit nezávislé obsahové porovnání včetně počtů a pořadí mediálních výskytů. Zkontrolovat také odkazy a technické výluky.
3. Zopakovat browser kontroly čtyř šířek, zvětšení textu a bez JS. Prohlédnout každou stránku včetně konce, všechny typy obrázků a galerie. U ořezů kontrolovat motiv a text uvnitř snímku.
4. Ověřit formulářové scénáře lokálně v capture režimu včetně chybové odpovědi v novém vzhledu. Žádné skutečné odeslání.
5. Opravit lokální regrese v autorizovaném rozsahu, zaznamenat je a znovu ověřit dotčenou část. Významný nový designový spor předložit uživateli místo svévolné přestavby.
6. Připravit konkrétní náhled nebo snímky pro majitelku. Uživatel je může předat; agent neposílá zprávy nebo e-maily třetím osobám. Získat její výslovné schválení zprostředkované uživatelem a zapsat, které verze se týká.
7. Připravit ověřený lokální release a aktualizovat handoff/STATUS/WORKLOG. Schválení vzhledu nesmí být zaměněno za oprávnění nasadit.

## DONE

Bez ztráty obsahu a funkčních regresí, velikost balíku stále splňuje zvolený tarif, majitelka schválila konkrétní vzhled. Pokud technické kontroly prošly, ale schválení chybí, uvést „technicky ověřeno, čeká na schválení“; B2 není celá DONE. Skončit před C1.
